# BeadDialog block layout (`BLOCKUI_BEAD.dlx`)

The real block roster, as generated by NX 2412's Block UI Styler — reconciled with `BlockAccessor.cs` after
the original placeholder layout in this doc turned out not to match. Class name is `BLOCKUI_BEAD` (root
namespace), not `BeadDialog`.

| Block ID | Type | Role |
|---|---|---|
| `selection0` | Selection (SelectObject) | Curve/edge/feature selection — scope to Curve + Edge + Feature in the Styler's selection filter, since a user may select curves/edges *or* an existing Bead feature directly. |
| `btn_ClearAll` | Button | Clears the current selection and resets dialog state. |
| `list_SelectionInfo` | List Box | One row per selected item, showing its create/edit/blocked status (`BeadDialogPresenter.UpdateSelectionInfoList`). |
| `ShtMetal` | Tree Control | Everything sheet-metal/material/status: Body, Thickness, Material (in-place editable dropdown when unassigned), Mode, SPEC Thickness, Allowed Materials, Error — two columns ("Property"/"Value"), columns/rows built at runtime in `BlockAccessor.PopulateSheetMetalTree`, not design-time in the .dlx. |
| `enum_BeadStd` | Enumeration (drop-down list) | Standard picker — chosen first, filters `enum_BABead`. |
| `enum_BABead` | Enumeration (drop-down list) | SPEC picker ("BA Bead") — filtered to the chosen Standard's rows that validate against the current sheet metal. |
| `double_R` | Double | SPEC's Radius/RAD S — locked read-only preview (`ReadOnlyValue = true`) once populated from the chosen SPEC. |
| `double_W` | Double | SPEC's Width — locked read-only preview, same as above. |
| `double_H` | Double | SPEC's Depth/Height — locked read-only preview, same as above. |
| `double_PRAD` | Double | SPEC's Die Radius — locked read-only preview, same as above. |
| `label_Image` | Static Text (Label) | Decorative bead cross-section diagram — no accessor entry, no wiring. |
| `group0`, `super_section0`, `group`, `group1`, `separator0` | layout only | No accessor entries. |

## Wiring the generated file (`BLOCKUI_BEAD.cs`)

This NX version's Styler generates `update_cb` dispatching by **block-reference equality**
(`if (block == selection0) ...`), not by name, and does **not** generate a separate named callback per
button — a button's click also routes through `update_cb`. Both differ from the with-block-ui.md skill
doc's generic example; the actual generated shape (confirmed by reading the real output) is:

```csharp
// >>> HAND-EDITED — re-add after any Styler regeneration <<<
public void initialize_cb()
{
    // ... existing FindBlock resolution ...
    Presenter?.Initialize();
}

public int update_cb(NXOpen.BlockStyler.UIBlock block)
{
    if (block == selection0)      Presenter?.OnSelectionChanged();
    else if (block == btn_ClearAll)    Presenter?.OnClearAllClicked();
    else if (block == enum_BeadStd)    Presenter?.OnStandardChanged();
    else if (block == enum_BABead)     Presenter?.OnSpecChanged();
    return 0;
}

public int apply_cb() => Presenter?.OnApply() ?? 1;
// ok_cb already calls apply_cb() internally in the generated stub — no separate wiring needed.
// >>> END HAND-EDITED <<<
```

Also hand-added to the generated class (see its own banner comments):

```csharp
public NXOpen.BlockStyler.BlockDialog TheDialog => theDialog;
public NxAdapters.Ui.BeadDialogPresenter Presenter { get; set; }
```

`BeadCommand.cs` has the rest of the wiring (`new BLOCKUI_BEAD()`, `BlockAccessor`, `BeadDialogPresenter`,
`dialog.Launch()`/`.Dispose()`).
